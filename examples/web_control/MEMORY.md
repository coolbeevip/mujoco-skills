# 物体观测记忆

办公室场景使用头部 RGB-D 记录已观察物体。当前识别范围是红、蓝、黄、绿、紫色小球，也会保留尚未通过球面验证的颜色候选。不是任意物体识别器；同色多个球的独立跟踪尚不支持。

## 如何查看

在控制台的模型决策记录区展开“已观察物体”，查看当前世界中的物体名称、最后水平位置和可见状态。颜色候选没有可靠深度时显示“尚未可靠定位”。

“查看持久化记录”打开 `/api/object-memory`，返回最近 200 条“场景实例—物体”的最新记录，包括之前场景的历史记录。完整的历次观测保存在数据库中，不受这个接口展示数量限制。

## 保存内容

服务启动后使用 `examples/web_control/.memory/objects.sqlite3` 保存观测，不需要额外安装数据库。目录被 Git 忽略，不随代码提交。记录包含：

- 物体名称、颜色、候选/球体类型与观测来源。
- 最后通过深度验证的水平坐标 `[x, y]`，单位为米，坐标系与办公室平面图一致。
- 首次、最后观测的 UTC 时间、仿真时间，以及当时机器人位姿。
- 当前采样是否可见、当前位置是否刚经过深度验证。

只有从头部图像和深度反投影得到的位置会被保存，不读取球的仿真坐标。暂停时不会对同一仿真时刻重复采样；运行时最多每 0.2 秒仿真时间采样一次。未开启视觉任务时也会记录预览中观察到的物体，不额外调用大模型。

## 记忆与导航

换任务不清空当前世界的记忆。遮挡、离开视野、超过 90 秒或路线失败，都不会删除“曾经看到”的事实。路线失败只排除相应接近方向，重新规划其他停靠点或外围观察点。周期性复查不重新开始已保留的绕行路线。

最后位置不保证物体仍在那里。重新看到后更新位置；只有当前图像与 RGB-D 满足到达条件才允许确认完成。只有颜色候选、尚无可靠位置时，不会编造坐标或自动导航到猜测的位置。

重置、重新加载场景或重启服务会创建新的世界实例。旧记录仍保存在磁盘，但标记为历史，不能直接用来控制新世界中的机器人；需要重新观察确认。

数据库不自动清理，会随观测增长。需要备份时，停止服务后复制整个 `.memory` 目录。记录写入失败会暴露为服务/任务错误，不会静默删除或重建数据库。

## 本地验证

```bash
examples/microduck/.venv/bin/python -m unittest discover -s examples/web_control/tests -q
examples/microduck/.venv/bin/python examples/web_control/office_route_smoke.py
```

路线演示使用固定响应验证真实步行、进入 103、目标发现与接近，不调用远程模型；不能替代真实模型下的场景验收。
